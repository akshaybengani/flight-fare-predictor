# FareSight QA report, round 2

Tester: independent, first-time non-technical user (revenue manager). Browser UI only at http://localhost:5055. Date of test: 17 Nov 2026 (app clock). Engine left at XGBoost (default) and light theme restored.

Not covered (tool limits / budget): I did not toggle "Include airlines that no longer operate" (I only verified the default-hidden behaviour and the wording), did not test the empty-date error, did not time searches with a stopwatch (observations only), did not walk every page of the unfiltered 21-page list, and did not test Premium Economy or Business.

## (a) Verdict

With fixes: not as it stands. The tag/card logic is now consistent and the explanations are much better, but the Model & Insights page still says in several places that HistGradientBoosting is "the current model" while search and Metrics say XGBoost is active. That is a visible contradiction in the one area the client will ask about. Separately, the first page of default results for Delhi to Mumbai is full of flights with an identical Listed fare (₹2,410) and vague time windows, which looks fake. And any visitor can switch the engine (shared across everyone) to Neural net, which then shows ₹12,773 against a listed ₹2,410 ("up 430%") with no warning. Fix the stale "current" wording, hide or protect the engine selector for the demo, and explain the repeated Listed prices, and it is demo-able.

## (d) What works well

- Tag, filter, card and counts now agree on all four required routes (Part A1).
- The persistent bold "not live prices" statement plus the accuracy sentence that updates per engine (XGBoost 93/87/68, Random Forest 92/87/44, Neural net 87/80/47).
- Details page: "What the model was given" table and the plain-language paragraph under the card (e.g. SG 8483 "FareSight's own estimate for today is ₹5,290. These are estimates, not promises.").
- Friendly errors and empty states (same cities, no flights on date, "Nothing here is expected to get cheaper"). No stale results.
- Shareable URL state, working Back button, market stays chosen.
- Engine switching: toast confirmation, engine named on the results page ("Engine: XGBoost"), accuracy line changes; switching MLP back to XGBoost restored 93/87/68 and "Engine: XGBoost" in the same session without mixed results that I could see.
- Light and dark themes both legible (search, Details, Model & Insights); phone (375x812) and tablet (768x1024) layouts reflow with no horizontal overflow seen; on phone the Model & Insights tabs wrap to rows.
- Honest content on Model & Insights (US tab: the model only barely beats "price stays the same", 93.3% vs 93.0%; licence note about non-commercial weather data).

## (e) Top 5 fixes before tomorrow

1. Remove "(current)" / "This is the current model" / "current model is filled red" for HistGradientBoosting everywhere and drive it from the active engine (N-01).
2. Explain or fix the repeated Listed prices (₹2,410, ₹5,953, ₹2,359) and the "time window" cards that dominate the cheapest-first page; at minimum default-sort so these do not fill page 1 (N-02, N-10).
3. Lock or hide the engine selector for the demo (or add a visible warning on weak engines and a "reset to XGBoost" button), since it is global for all users and Neural net gives ₹12,773 vs ₹2,410 (N-03, N-07).
4. Reconcile Model & Insights numbers and stale first-model text (speed/size, 66% vs 68%, "Importance (first model)", blank parameter meanings, te_flight etc.) (N-04, N-05, N-06).
5. Add one line near the filters stating that "Price may drop" is about a later fall, not today's "down X%" on the card, and clarify "Expected low" vs the chart minimum; fix the US hero "Listed today" wording and the silent ORD to JFK route swap (N-11, N-12, N-08).
